# Детерминизм NBT-сериализации чанков (2026-07-16)

**Машина:** AMD Ryzen 7 7700 (8c/16t), governor=performance, btrfs, NVMe.
**Ветка:** `fix/io-path`, фикс — `57772d4e`.
**Команды:** локализация — дамп 64 noise-чанков (сид 42, (0..8)², Full) в двух
процессах + побайтовый `cmp` и по-компонентные хэши; приёмка —
`cargo test -p pumpkin-world --test nbt_determinism` (дочерний процесс через
`std::process::Command` + `current_exe()`); бенчи — интерлив заранее собранных
бинарей + `perf stat -e instructions`.

## Симптом и реальный масштаб

Заявленный симптом: ~578 байт разницы NBT между запусками процесса.
Фактически найдено два класса:

1. **Порядок тегов** (длина совпадает, байты нет) — у всех 64 чанков.
2. **Разный сгенерированный контент**: **6743 блока** различались между двумя
   запусками (от 2 до 515 блоков на чанк, дельты длины до −4138 байт —
   исчезающие секции света). Это полноценное нарушение бит-точности
   генерации, а не только сериализации.

## Источники недетерминизма (все найденные)

| # | Место | Класс | Механизм |
|---|---|---|---|
| 1 | `pumpkin-world/src/generation/feature/features/vegetation_patch.rs:88,206` (+ `waterlogged_vegetation_patch.rs:73,85`) | **контент** | `place_ground_patch` возвращал `HashSet<BlockPos>` (std RandomState), `distribute_vegetation` итерировал его, потребляя RNG на позицию → порядок ASLR-зависим → пещерная растительность (мох/глина/дрипстоун) генерилась по-разному в каждом процессе |
| 2 | `pumpkin-nbt/src/compound.rs:35` | порядок | `NbtCompound.child_tags: HashMap<Box<str>, NbtTag>` → порядок тегов любого вручную собранного компаунда случаен по процессам |
| 3 | `pumpkin-world/src/tick/mod.rs:119` | порядок | `ScheduledTick::serialize` строил `NbtCompound` (см. №2) — первая наблюдаемая точка расхождения в дампах (`fluid_ticks`) |
| 4 | `pumpkin-world/src/poi/mod.rs:73,80` | порядок | `PoiChunkData.sections` и `PoiRegion.entries` — std HashMap, сериализуются/итерируются в poi-файлы |

Проверены и чисты: палитры (map только для lookup), `PLACED_FEATURES`/
`CONFIGURED_FEATURES` (только `.get`), geode-HashSet'ы (только `contains`),
тик-шедулер (FxHashSet — детерминированный хэшер, только membership),
движок света (Fx + VecDeque; расхождения света были следствием №1),
entity-путь (`Vec<NbtCompound>` — порядок компаундов чинится №2),
blender/generator (FxHashMap с целочисленными ключами).

## Выбранные порядки (контракты стабильности — навсегда)

- `NbtCompound` → `BTreeMap`: теги пишутся в **лексикографическом порядке
  байтов ключа**. Задокументировано в докстроке типа. Примечание: Java пишет
  теги в порядке своего HashMap — байт-в-байт совпадение регион-файлов с
  ванилью потребовало бы эмуляции этого порядка; вынесено в TODO ветки
  `feat/bitexact-tests`.
- Тики → фиксированная serde-структура, порядок полей **i, p, t, x, y, z**.
- Vegetation patch → **порядок сканирования колонок** (dx внешний, dz
  внутренний); дубликатов нет по построению (одна колонка — максимум одна
  позиция).
- POI: секции — лексикографический порядок строковых ключей ("−1" < "0" <
  "10" < "2" — не числовой, но стабильный); записи — порядок кортежа (x,y,z).

## Производительность

- `full_chunk_generation` против baseline `main`: **+0.80%** (criterion:
  «within noise threshold»; контент генерации изменился легитимно — порядок
  вегетации теперь фиксирован).
- Hot-сценарий `chunk_io` (сериализация+LZ4, 64 чанка): стеночные замеры
  сегодня некогерентны между бинарями (вариант-подмножество медленнее
  надмножества; «только контент» ±12% без изменений кода сериализации) —
  классический шум код-лейаута на LZ4-петле поверх термодрейфа; внутри
  одного бинаря воспроизводимость ±0.5%. Решающий замер —
  **инструкции CPU** (layout-нечувствительны): base 605.6 млрд →
  patched **529.0 млрд (−12.7%)**, воспроизводимо в двух повторах.
  Алгоритмической регрессии нет; удаление NbtCompound из сериализации тиков
  убрало аллокацию на тик.

## TODO / отмечено

- Эмуляция Java-порядка тегов HashMap для байт-в-байт паритета регион-файлов
  с ванилью — `feat/bitexact-tests` (наш контракт: сортировка ключей).
- Вегетация: ванильный Java-код итерирует `HashSet<BlockPos>` со своим
  (детерминированным по контенту) порядком — для бит-точного паритета
  растительности с ванилью потребуется воспроизвести порядок Java-HashSet;
  текущий контракт (скан колонок) детерминирован, но с ванилью не совпадает.
  Тоже `feat/bitexact-tests`.
- pumpkin-nbt — shared-крейт: изменение минимальное (тип контейнера +
  `const fn new`), но затрагивает все NBT-пути сервера (плюс: единый порядок
  тегов везде).
- Стеночный бенч hot-сценария на этой машине не разрешает <2% между разными
  бинарями — для будущих приёмок сериализации использовать
  `perf stat -e instructions` или изолированный бенч `to_bytes`.
