# CLAUDE.md — Pumpkin-plus

## Миссия

Pumpkin-plus — приватный форк [Pumpkin](https://github.com/Pumpkin-MC/Pumpkin) (Minecraft-сервер на Rust).
Цель: **самая быстрая ванильно-совместимая генерация мира среди всех серверов.**

Конкретная измеримая цель: на Ryzen 7 7700 устойчиво генерировать **>460 чанков/сек**
при прегенерации (эталон: Java + Fabric + C2ME(OpenCL) + Lithium + ScalableLux + Chunky
на этой же машине = ~450–467 cps) — и не падать, в отличие от эталона.

Вторичные цели (целевые сценарии на живом сервере):
- Ryzen 7 7700 + RTX 3070 Ti: 30 игроков одновременно бегут/летят на элитрах, render distance 12, без лагов.
- i5-10400F + RTX 3070 Ti: 6 игроков на элитрах, RD 20.
- FX-4300 + HD 7750, HDD: 10 бегущих игроков, RD 8.

## Незыблемые ограничения (нарушение = откат изменения)

1. **Бит-точность ванильной генерации.** Мир с сидом X обязан совпадать с ванильным
   Java-сервером той же версии байт-в-байт (блоки, биомы, структуры, aquifers).
   - Весь шум считается в **f64 (double)**. Замена на f32 запрещена, даже частичная,
     без доказательства тестами, что результат не меняется.
   - Запрещено допускать FMA-контракцию, меняющую биты: на GPU — квалификатор
     `precise` в GLSL; на CPU — не включать `-C target-feature` / fast-math флаги,
     меняющие результат существующих тестов.
   - Существующие тесты сверки с ванилью (`sample_legacy`, `sample_xoroshiro`,
     `steep_matches_vanilla`, `configured_seed_generates_vanilla_ancient_city_chunk` и т.д.)
     — священны. Их нельзя ослаблять, помечать ignore или подгонять константы.
2. **`cargo test -p pumpkin-world` зелёный** после каждого изменения.
3. **Бенчмарки не регрессируют.** После изменения в горячем пути:
   `cargo bench -p pumpkin-world -- --baseline main`. Регрессия >2% в любом
   бенче без явного обоснования в PR = откат.
4. **Формат мира на диске не меняется** без opt-in флага в конфиге. Дефолт —
   совместимость с существующими мирами.
5. `unsafe` — только с комментарием-обоснованием SAFETY. Никакого `unsafe` для
   «ускорения», если есть безопасная альтернатива в пределах 5% скорости.
6. Никаких новых обязательных зависимостей от GPU: сервер обязан собираться и
   работать на машине без Vulkan (GPU-бэкенд — feature-флаг + рантайм-фолбэк на CPU).
7. Один PR = одна идея. Маленькие диффы. Ветка → PR в собственный репо → merge.

## Контракты детерминизма (введены в fix/io-path, менять нельзя)

Одинаковые данные чанка обязаны сериализоваться байт-в-байт одинаково между
процессами и машинами. Зафиксированные порядки (см. docs/baseline/nbt-determinism-2026-07-16.md):

1. **Теги NBT-компаундов** — лексикографический порядок байтов ключа
   (`NbtCompound` на `BTreeMap`, pumpkin-nbt/src/compound.rs). Не возвращать
   hash-контейнеры: RandomState ASLR-зависим.
2. **Тики** — фиксированный порядок полей `i, p, t, x, y, z`
   (serde-структура в pumpkin-world/src/tick/mod.rs, не компаунд).
3. **Vegetation patch** — порядок сканирования колонок (dx внешний, dz
   внутренний), `Vec` вместо `HashSet<BlockPos>`: итерация потребляет RNG,
   порядок определяет сгенерированные блоки.
4. В генерации и сериализации std `HashMap`/`HashSet` допустимы только для
   lookup/membership; любая итерация с эффектом на RNG или байты — только
   детерминированные контейнеры (Vec, BTreeMap, FxHash* с не-указательными
   ключами). Гейт: тест `pumpkin-world/tests/nbt_determinism.rs`
   (сравнение хэшей с дочерним процессом — ASLR ловится только так).

## Базовая линия (Ryzen 7 7700, single-thread, cargo bench, master на момент форка)

| Стадия | Время | Доля |
|---|---|---|
| full_chunk_generation | **31.0 мс** | 100% |
| lighting_generation | 13.1 мс | ~42% ← самая жирная цель |
| noise_generation | 11.5 мс | ~37% ← вторая цель, GPU-кандидат |
| surface_generation | 2.7 мс | ~9% |
| carvers_generation | 1.6 мс | ~5% |
| biomes_generation | 0.93 мс | ~3% |
| features_generation | 0.76 мс | ~2% |
| structure_starts + references | ~0.14 мс | <1% |

concurrent_full_pipeline_16_chunks_4_threads: 137 мс (~117 чанков/с на 4 потоках,
масштабирование ~91%/поток). Экстраполяция на 16 потоков 7700: ~250–290 чанков/с.

Актуальные замеры — в `docs/baseline/`:
- `dirty-hygiene-2026-07-16.md` — повторный визит: 4 файла/135 КБ → 0.
- `chunk-io-2026-07-16.md` — путь записи (PR0): усиление записи ×8.51 при
  наполнении региона (write_all) vs ×1.03 (write_in_place); чтение ×7.51 в
  обоих режимах из-за эвикции сериализатора.
- `nbt-determinism-2026-07-16.md` — источники недетерминизма и контракты.

Criterion baseline `main` живёт в `target/` и теряется при очистке —
пересоздавать на нужном коммите stash-манёвром
(`cargo bench -p pumpkin-world -- --save-baseline main`).
Бенчи IO: `cargo bench -p pumpkin-world --bench chunk_io --features io-bench-counters`
(байтовые счётчики; без фичи время меряется, байты — `na`).

## Дорожная карта (ветки)

Порядок важен: побеждаем в порядке жирности и простоты, GPU — последним.

1. `fix/io-path` — путь записи чанков (В РАБОТЕ, коммиты 6fcc5697…ceb3f836):
   - СДЕЛАНО: dirty-гигиена Proto-чанков (чтение территории не пишет на диск;
     флаг `ProtoChunk.modified`); восстановление dirty при ошибке записи;
     фикс livelock flat-миров (Structure*-стадии не выставлялись); PR0 —
     измерительная обвязка (бенчи chunk_io + байтовые счётчики за фичей
     `io-bench-counters`); детерминизм NBT/генерации между процессами.
   - ДАЛЬШЕ (PR1+): LRU-кэш сериализаторов регионов (сейчас каждый сейв =
     полное перечитывание + эвикция, ×7.51 чтения на прегене); решение по
     дефолту write_in_place (нужен сценарий «1 грязный чанк из 64»);
     асинхронный write-behind и батчинг; вынос upgrade_to_level_chunk из
     единственной io_write-задачи; формат Linear как opt-in.
   - ИЗВЕСТНЫЙ БАГ (кандидат в отдельный PR): гонка на шатдауне — чанки,
     прилетающие от ген-потоков после save_all_chunk(true), принимаются, но
     не сохраняются (schedule.rs, дренаж после break).
2. `feat/bitexact-tests` — обвязка бит-точности: дампы эталонных чанков с
   ванильного Java-сервера (разные сиды/биомы/структуры), тест «Pumpkin генерирует
   байт-в-байт то же». Это гейт для всех последующих веток.
   Уже известные расхождения с Java (из fix/io-path): порядок тегов NBT
   (у нас сортировка, Java — порядок своего HashMap) и порядок обхода
   вегетации (Java итерирует свой HashSet). Для байт-паритета регион-файлов
   потребуется эмуляция порядков Java либо канонизация при сравнении.
3. `feat/pregen` — встроенный прегенератор (аналог Chunky): команда, радиус,
   спиральный обход, батчи ~256 чанков, троттлинг, отчёт cps/ETA, устойчивость
   к рестарту. Метрика: время полного прогона радиуса 2000 против эталона C2ME.
4. `feat/scheduler-predictive` — планировщик генерации: приоритетная очередь
   (конус по вектору скорости игрока > круг вокруг игрока > фоновая прегенерация),
   лимиты на игрока, чтобы один элитрщик не голодал остальных.
5. `feat/lighting-fast` — переработка освещения по мотивам Starlight/ScalableLux
   (репо: PaperMC/Moonrise, Spottedleaf). Цель: 13.1 мс → <4 мс на чанк.
   Бит-точность света проверяется теми же дампами.
6. `feat/gpu-noise` — GPU-оффлоад density function. Детали ниже.

## GPU-фаза: принятые решения

- **API: Vulkan** через крейт `ash`. Ядра — **GLSL compute** → SPIR-V.
  - `#extension GL_ARB_gpu_shader_fp64 : require`, вся шумовая математика в double.
  - Квалификатор `precise` на всех выражениях, где FMA-контракция может изменить биты.
  - Валидационные слои Vulkan включены в debug-сборках всегда.
- Изолированный крейт `pumpkin-gpu` с узким трейтом вида
  `fn fill_density_grids(seed, batch: &[ChunkPos]) -> Vec<DensityGrid>`.
  Бэкенды за трейтом: `vulkan` (основной), CPU-фолбэк (обязательный), место под
  альтернативы. Остальной код о Vulkan не знает.
- На GPU выносится **только заполнение сеток плотности (шум)** батчами 64–256 чанков.
  Aquifers, surface rules, features, структуры, свет — на CPU (последовательный RNG).
- Два пути памяти: integrated GPU (zero-copy, host-visible память) и discrete
  (staging-буферы, явные трансферы, оверлап трансфера и счёта). Выбор по типу устройства.
- Конвейер: GPU считает шум батча N+1, пока CPU делает поздние стадии батча N.
- Референсы ядер: OpenCL-ядра C2ME (структура), cubiomes (формулы на C),
  декомпил ванили через DecompilerMC (спорные места).
- Критерий приёмки: тест бит-точности проходит на GPU-пути; выигрыш меряется
  бенчем полного пайплайна, не изолированным ядром.
- Помнить про Амдала: шум = 11.5 мс из 31. Даже бесплатный шум даёт максимум ~×1.6
  к полному пайплайну. GPU — не серебряная пуля, а освобождение CPU-ядер.

## Рабочий процесс агента

Перед началом любой задачи:
```bash
git status                     # чистое дерево, правильная ветка
cargo test -p pumpkin-world    # зелёная точка отсчёта
```

После изменения:
```bash
cargo test -p pumpkin-world
cargo bench -p pumpkin-world -- --baseline main   # если трогал горячий путь
cargo clippy -p pumpkin-world -- -D warnings      # + затронутые крейты
```
(`cargo clippy --workspace` в этом чекауте сломан: отсутствует
`pumpkin-plugin-wit/v0.1` — известное состояние, не чинить попутно.)

Результаты значимых бенчей складывать в `docs/baseline/` с датой.
В коммит-сообщении: что изменено, цифра до / цифра после.

Уроки бенчмаркинга (см. nbt-determinism-2026-07-16.md):
- Стеночное время между РАЗНЫМИ бинарями на этой машине шумит до ±10%
  (код-лейаут LZ4-петли + термодрейф); внутри одного бинаря — ±0.5%.
- Для ворот «регрессия >2%» на пути сериализации: A/B интерливом заранее
  собранных бинарей, а решающий аргумент — `perf stat -e instructions`
  (layout-нечувствителен).

Запрещено агенту без явного запроса пользователя:
- менять версии зависимостей и toolchain;
- трогать файлы в `pumpkin-nbt`, `pumpkin-data` (генерируемые данные);
- «чинить» упавший тест бит-точности правкой теста;
- глобальные rustflags/фичи, влияющие на числовые результаты.

## Железо проекта

- Дев-машина: Ryzen 7 7700 (8c/16t Zen 4), RTX 3070 Ti (FP64 = 1/64, ~0.29 TFLOPS —
  поэтому double на GPU НЕ бесплатен), NVMe.
- Валидационные машины: i5-10400F + 3070 Ti; FX-4300 (без AVX2! отдельно проверять,
  что сборка и скорость не деградируют) + HD 7750 + HDD/btrfs (для мира — chattr +C).
- Стенд-ноутбук: Ryzen 3 5400U (4c/8t Zen 2, Vega 8, 24 GB) — быстрые итерации.
